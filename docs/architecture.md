# Архитектура системы


## Общая схема

Приложение построено по классической трёхуровневой архитектуре:

**Уровень 1 — Клиент (браузер):**
- Технологии: HTML5, CSS3 (фреймворк Tabler), JavaScript (vanilla)
- Взаимодействие с сервером: через REST API с использованием fetch()

**Уровень 2 — Сервер приложений:**
- WSGI-сервер: Gunicorn (production) или встроенный сервер Django (development)
- Фреймворк: Django 5.x + Django REST Framework
- Обработка запросов: маршрутизация, аутентификация, бизнес-логика, валидация

**Уровень 3 — База данных:**
- Локальная разработка: SQLite (файл db.sqlite3)
- Production: PostgreSQL (облачный сервис на Render)
- Подключение: через переменную окружения DATABASE_URL

**Дополнительные компоненты:**
- Статические файлы: обслуживаются через WhiteNoise без внешнего веб-сервера
- CDN: фреймворк Tabler загружается с jsDelivr



## Компоненты системы

### 1. Frontend (браузер)
- **Технологии:** HTML5, CSS3 (фреймворк Tabler), JavaScript (vanilla)
- **Взаимодействие с backend:** через REST API с использованием `fetch()`
- **Основные страницы:**
  - `/crud-groups/` — управление учебными группами
  - `/inventory/` — заявки на выдачу оборудования
  - `/admin/` — панель администратора Django

### 2. Backend (сервер приложений)
- **WSGI-сервер:** Gunicorn (production) или встроенный сервер Django (development)
- **Фреймворк:** Django 5.x
- **REST API:** Django REST Framework
- **Приложения:**
  - `accounts` — аутентификация и управление пользователями
  - `groups` — управление учебными группами
  - `inventory` — система заявок на оборудование

### 3. База данных
- **Локальная разработка:** SQLite (файл `db.sqlite3`)
- **Production:** PostgreSQL (облачный сервис на Render)
- **Подключение:** через переменную окружения `DATABASE_URL`

### 4. Статические файлы
- **Хранение:** директория `static/` (исходники) и `staticfiles/` (собранная статика)
- **Раздача в production:** WhiteNoise (без внешнего веб-сервера)
- **CDN:** фреймворк Tabler загружается с jsDelivr

## Взаимодействие компонентов

### Запрос на создание заявки:
1. Пользователь заполняет форму в браузере
2. JavaScript отправляет `POST /api/inventory/requests/` с JSON-телом
3. Django принимает запрос, проверяет аутентификацию и права доступа
4. DRF сериализатор валидирует данные
5. ViewSet выполняет транзакцию: создаёт заявку + резервирует оборудование
6. ORM записывает изменения в базу данных
7. Сервер возвращает HTTP 201 с JSON созданного объекта
8. JavaScript обновляет интерфейс без перезагрузки страницы

### Развёртывание:
- **Платформа:** Render (облачный хостинг)
- **Сборка:** автоматическая через `build.sh` при каждом push в Git
- **Переменные окружения:** настраиваются в панели Render
- **Миграции БД:** выполняются автоматически при сборке
