# Инструкция развёртывания на Render

## Подготовка

### Требования
- Аккаунт на GitHub
- Аккаунт на Render (https://render.com)
- Публичный репозиторий с исходным кодом проекта

### Переменные окружения
Проект использует следующие переменные окружения:

- `DJANGO_SECRET_KEY` — секретный ключ Django для подписи сессий и CSRF-токенов. Значение должно быть случайной строкой длиной не менее 50 символов.
- `DJANGO_DEBUG` — режим отладки. Для production должно быть установлено значение `False`.
- `DJANGO_ALLOWED_HOSTS` — список доменов, с которых принимаются запросы. Разделяются запятыми.
- `DJANGO_CSRF_TRUSTED_ORIGINS` — доверенные источники для CSRF-проверки. Указываются с протоколом `https://`.
- `DATABASE_URL` — строка подключения к PostgreSQL в формате `postgresql://USER:PASSWORD@HOST:5432/DBNAME`.

**Важно:** никогда не публикуйте фактические значения этих переменных в репозитории. Используйте только файл `.env.example` как шаблон с примерными значениями.

## Шаг 1. Создание PostgreSQL на Render

1. Войдите в панель управления Render.
2. Нажмите кнопку **New** и выберите тип сервиса **PostgreSQL**.
3. Заполните форму создания:
   - **Name:** `django-db` (или любое другое имя)
   - **Region:** `Oregon (US West)` — важно запомнить регион
   - **Instance Type:** `Free`
4. Нажмите **Create Database** и дождитесь статуса **Available** (обычно 2-3 минуты).
5. Перейдите в раздел **Connections** созданной базы данных.
6. Скопируйте значение **Internal Database URL** — оно понадобится на следующем шаге.

## Шаг 2. Создание Web Service

1. Вернитесь в панель Render и нажмите **New** → **Web Service** → **Build and deploy from a Git repository**.
2. Выберите репозиторий проекта из списка и нажмите **Connect**.
3. Заполните форму настройки:
   - **Name:** `django-app`
   - **Region:** тот же, что у PostgreSQL (например, Oregon) — это важно для использования внутреннего подключения к базе данных
   - **Branch:** `main`
   - **Root Directory:** оставить пустым
   - **Runtime:** `Python 3`
   - **Build Command:** `bash build.sh`
   - **Start Command:** `gunicorn config.wsgi:application --bind 0.0.0.0:$PORT`
   - **Instance Type:** `Free`
4. Пока не нажимайте **Create Web Service** — сначала добавьте переменные окружения.

## Шаг 3. Настройка переменных окружения

В форме создания Web Service прокрутите страницу до раздела **Environment Variables** и добавьте пять переменных:

- `DATABASE_URL` — вставьте Internal Database URL, скопированный на Шаге 1.
- `DJANGO_SECRET_KEY` — нажмите кнопку **Generate** рядом с полем для автоматической генерации случайного значения.
- `DJANGO_DEBUG` — установите значение `False`.
- `DJANGO_ALLOWED_HOSTS` — укажите домен сервиса без протокола (например, `django-app.onrender.com`). Точный домен будет известен после создания сервиса.
- `DJANGO_CSRF_TRUSTED_ORIGINS` — укажите домен сервиса с протоколом (например, `https://django-app.onrender.com`).

## Шаг 4. Сборка и запуск

1. Нажмите **Create Web Service**.
2. Платформа Render автоматически выполнит следующие действия:
   - Клонирует репозиторий из GitHub.
   - Выполнит команду сборки `bash build.sh`, которая установит зависимости из `requirements.txt` и соберёт статические файлы.
   - Запустит сервер приложений Gunicorn.
3. Следите за журналом **Logs** — при успешном завершении всех этапов сервис перейдёт в статус **Live** и получит публичный HTTPS-адрес.

## Шаг 5. Выполнение миграций

Если команда `python manage.py migrate` не включена в файл `build.sh`, её необходимо выполнить вручную после первого развёртывания:

1. Откройте вкладку **Shell** сервиса в панели Render.
2. Выполните команды:

    python manage.py migrate
    python manage.py createsuperuser

3. Закройте консоль Shell.

## Шаг 6. Проверка работоспособности

1. Откройте публичный адрес сервиса в браузере (например, `https://django-app.onrender.com`).
2. Проверьте endpoint здоровья по адресу `https://django-app.onrender.com/healthz/` — должен вернуться JSON `{"status": "ok"}` с HTTP-статусом 200.
3. Откройте админ-панель по адресу `/admin/` и войдите под суперпользователем, созданным на Шаге 5.
4. Создайте тестовую запись через интерфейс и обновите страницу — данные должны сохраниться в базе данных PostgreSQL.

## Важные замечания

- **SQLite и PostgreSQL — разные базы данных.** Данные из локальной SQLite не переносятся автоматически в облачную PostgreSQL.
- **Internal Database URL** работает только между сервисами, размещёнными в одном регионе Render.
- **Бесплатный тариф Render** засыпает после 15 минут неактивности — первый запрос после простоя может выполняться до 50 секунд.
- **Статические файлы** обслуживаются через WhiteNoise, внешний веб-сервер (Nginx) не требуется.
- **Пароли и токены** никогда не должны публиковаться в репозитории или отчёте.
