# Схема базы данных

Проект использует три Django-приложения, каждое из которых содержит собственные модели. Связи между моделями реализованы через внешние ключи `ForeignKey`.

## Приложение accounts

Модель пользователя (наследует стандартную модель Django или кастомную). Хранит учётные данные для аутентификации во всех приложениях проекта.

**Ключевые поля:**
- `id` — уникальный идентификатор (первичный ключ)
- `username` — имя пользователя (уникальное)
- `email` — адрес электронной почты
- `password` — хэш пароля
- `is_staff` — признак доступа к админ-панели
- `is_active` — признак активности аккаунта

## Приложение groups

### Модель Faculty (Факультет)

Справочник факультетов, к которым привязаны учебные группы.

**Ключевые поля:**
- `id` — уникальный идентификатор
- `name` — название факультета (уникальное)
- `code` — код факультета (уникальный)

### Модель Group (Учебная группа)

Основная сущность приложения управления учебными группами.

**Ключевые поля:**
- `id` — уникальный идентификатор
- `name` — название группы (уникальное)
- `faculty` — внешний ключ на модель Faculty (связь «многие к одному»)
- `year` — год набора
- `created_at` — дата и время создания

**Связи:**
- `Group.faculty` → `Faculty.id` (many-to-one, `on_delete=PROTECT`)

## Приложение inventory

### Модель Equipment (Оборудование)

Справочник единиц оборудования с учётом остатков на складе.

**Ключевые поля:**
- `id` — уникальный идентификатор
- `name` — название оборудования
- `category` — категория (lab, pc, measure, tool)
- `inventory_number` — инвентарный номер (уникальный)
- `total_stock` — общее количество единиц
- `available_stock` — количество, доступное для выдачи
- `location` — местоположение
- `created_at` — дата добавления в справочник

### Модель EquipmentRequest (Заявка на оборудование)

Основная сущность бизнес-процесса выдачи оборудования. Содержит конечный автомат состояний.

**Ключевые поля:**
- `id` — уникальный идентификатор
- `requester` — внешний ключ на модель пользователя (заявитель)
- `equipment` — внешний ключ на модель Equipment
- `quantity` — запрашиваемое количество
- `status` — текущее состояние (draft, approved, issued, returned, rejected)
- `purpose` — цель использования
- `created_at` — дата создания
- `updated_at` — дата последнего изменения

**Связи:**
- `EquipmentRequest.requester` → User (many-to-one, `on_delete=PROTECT`)
- `EquipmentRequest.equipment` → Equipment (many-to-one, `on_delete=PROTECT`)

**Конечный автомат состояний:**
- `draft` → `approved` (согласование) или `rejected` (отклонение)
- `approved` → `issued` (выдача) или `rejected` (отклонение)
- `issued` → `returned` (возврат)
- `returned` и `rejected` — терминальные состояния

### Модель RequestEvent (Событие заявки)

Журнал истории изменений заявок.

**Ключевые поля:**
- `id` — уникальный идентификатор
- `request` — внешний ключ на модель EquipmentRequest
- `actor` — внешний ключ на модель пользователя (инициатор действия)
- `action` — тип события (created, approved, issued, returned, rejected, deleted)
- `comment` — комментарий к действию
- `created_at` — дата и время события

**Связи:**
- `RequestEvent.request` → EquipmentRequest (many-to-one, `on_delete=CASCADE`)
- `RequestEvent.actor` → User (many-to-one, `on_delete=SET_NULL`)


## Используемая СУБД

- **Локальная разработка:** SQLite (файл `db.sqlite3` в корне проекта)
- **Production:** PostgreSQL (облачный сервис на Render, подключение через переменную `DATABASE_URL`)

Структура таблиц одинакова для обеих СУБД благодаря использованию Django ORM.
