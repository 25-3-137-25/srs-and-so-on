# Диагностика типичных ошибок

## 1. Ошибка DisallowedHost (HTTP 400)

**Симптом:** при обращении к сайту отображается страница с ошибкой `DisallowedHost`.

**Причина:** домен, с которого приходит запрос, не указан в переменной окружения `DJANGO_ALLOWED_HOSTS`.

**Диагностика:** в журнале **Logs** сервиса на Render будет запись `Invalid HTTP_HOST header` с указанием проблемного домена.

**Решение:**
1. Откройте панель Render, выберите ваш Web Service и перейдите в раздел **Environment**.
2. Найдите переменную `DJANGO_ALLOWED_HOSTS`.
3. Установите значение, равное домену сервиса (без протокола `https://`), например: `myapp.onrender.com`.
4. Перезапустите сервис через **Manual Deploy**.

---

## 2. Ошибка ModuleNotFoundError при сборке

**Симптом:** сборка падает с сообщением `ModuleNotFoundError: No module named '...'`.

**Причина:** в файле `requirements.txt` отсутствует необходимый пакет.

**Диагностика:** в журнале сборки видно, на каком импорте упал процесс.

**Решение:**
1. Локально выполните `python -m pip install <название_пакета>`.
2. Обновите файл зависимостей командой `python -m pip freeze > requirements.txt`.
3. Закоммитьте изменения и отправьте в репозиторий — Render автоматически перезапустит сборку.

---

## 3. Ошибка подключения к базе данных

**Симптом:** в журнале Logs видны ошибки `connection refused` или `password authentication failed`.

**Причина:** неверная строка подключения в переменной `DATABASE_URL`.

**Диагностика:** проверьте формат строки: `postgresql://USER:PASSWORD@HOST:5432/DBNAME`.

**Решение:**
1. Откройте сервис PostgreSQL на Render и перейдите в раздел **Connections**.
2. Скопируйте **Internal Database URL**.
3. Обновите переменную `DATABASE_URL` в настройках Web Service.
4. Перезапустите сервис.

---

## 4. Статические файлы не загружаются (404)

**Симптом:** страница открывается, но стили и скрипты не применяются.

**Причина:** не выполнена команда `collectstatic` или неправильно настроен WhiteNoise.

**Диагностика:** в журнале сборки должна быть строка `python manage.py collectstatic --noinput`.

**Решение:**
1. Убедитесь, что в файле `build.sh` есть команда `python manage.py collectstatic --noinput`.
2. Проверьте, что в `settings.py` добавлен `WhiteNoiseMiddleware` и настроен `STATIC_ROOT`.
3. Перезапустите сборку через **Manual Deploy**.

---

## 5. Ошибка CSRF при POST-запросах

**Симптом:** при отправке формы возвращается HTTP 403 с сообщением `CSRF verification failed`.

**Причина:** в запросе отсутствует CSRF-токен или домен не указан в `DJANGO_CSRF_TRUSTED_ORIGINS`.

**Диагностика:** проверьте вкладку **Network** в DevTools браузера — заголовок `X-CSRFToken` должен присутствовать в запросе.

**Решение:**
1. Добавьте домен сервиса в переменную `DJANGO_CSRF_TRUSTED_ORIGINS` (с протоколом `https://`).
2. Убедитесь, что JavaScript корректно извлекает cookie `csrftoken` и передаёт его в заголовке `X-CSRFToken`.

## 6. Ошибка ImproperlyConfigured: Set DJANGO_SECRET_KEY

**Симптом:** приложение не запускается, в логах видна ошибка `ImproperlyConfigured`.

**Причина:** переменная `DJANGO_SECRET_KEY` не задана в окружении.

**Решение:**
1. Откройте раздел **Environment** сервиса на Render.
2. Добавьте переменную `DJANGO_SECRET_KEY` и нажмите **Generate** для генерации случайного значения.
3. Перезапустите сервис.

---

## 7. Таймаут сборки на Render

**Симптом:** сборка зависает и завершается по таймауту.

**Причина:** медленный ответ PyPI или большой размер зависимостей.

**Решение:**
1. В файле `build.sh` добавьте увеличение таймаута pip:

    python -m pip install --default-timeout=100 --retries 5 -r requirements.txt

2. Перезапустите сборку.

---

## 8. Данные пропадают после перезапуска сервиса

**Симптом:** созданные через интерфейс записи исчезают после перезапуска.

**Причина:** приложение использует локальную SQLite вместо облачной PostgreSQL.

**Диагностика:** проверьте переменную `DATABASE_URL` — если она не задана, Django использует SQLite, которая не сохраняется между перезапусками на Render.

**Решение:** задайте корректную переменную `DATABASE_URL`, указывающую на сервис PostgreSQL в том же регионе.
